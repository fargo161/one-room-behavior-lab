# Prototype Assumptions — v0.2.1

1. Normalized interpretation/state metrics use `0..1`; behavior bases may use `-1..1`.
2. Exact score ties use authored behavior order and record the reason.
3. No stochastic choice exists, so no seed is exposed.
4. Contact notice uses scenario-local visibility salience, attention match, alert, suspicion, and weak-attention penalty.
5. Public content may be interpreted by both observers, but only the direct recipient may accept its requested action or Deal.
6. Previously enacted behavior can be observed at the next Beat boundary. Neither character can use the other's newly selected same-Beat action during scoring.
7. The opportunity bridge is scenario-specific and requires an active monitoring plan plus direct observation of Drew's diverted attention.
8. Subject is semantic metadata/validation context without an independent v0.2.1 modifier.
9. Ask reason is authored wording/provenance without an independent v0.2.1 modifier.
10. Function reinterpretation is not implemented. The interpreted Function mirrors the selected intended Function.
11. `REDUCE_RISK`, `PRESERVE_RELATIONSHIP`, and `DISCHARGE_OBLIGATION` are partial player Functions: their real contributions are contextual and do not imply a universal state effect.
12. The first BASED Cue is dominant. A fixed 62:38 split is only this prototype's default; variable instance weighting remains unresolved.
13. An accepted action-bearing Deal creates a commitment. A claim-only Deal can create an accepted exchange without making its recipient debtor to an unrelated action.
14. Transfer completion requires one open offer and one compatible Mara/Drew intention pair; possession stays exclusive.
15. CSS faces and progressive text are schematic renders of the shared Performance Plan, not psychological classifiers.

Open questions—variable Vibe weighting, PSG-native semantic ownership, richer inference, generalized opportunity, and generalized coordinated action—remain intentionally unresolved.
