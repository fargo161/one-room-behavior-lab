# Design Boundaries — v0.2.1

## Classification

This lab is evidence for a design direction and a standalone executable reference, not a canonical PSG/BASED implementation. It has zero code-level PSG integration. Local Cue, Vibe, Function, status, mapping, and validation structures are prototype scaffolding whose semantic ownership is expected to migrate later.

## Scope

One room, Mara, Drew, one envelope, one exit, one unseen player, eight Beats maximum, and one structured player message maximum per Beat. The player controls communication conditions, not character behavior, movement, possession, truth, or environment events.

## Required separation

- Communication event is distinct from content access.
- Objective state is distinct from assumed, reported, inferred, observed, doubted, refuted belief.
- DPA social structure is distinct from BASED delivery expression.
- Delivery Vibe is distinct from execution Vibe.
- Intended Function is distinct from accepted application and derived pressure.
- Generated wording is distinct from structured mechanics.
- Selected intent is distinct from joint outcome and resolved performance wording.
- Mutation-time cause is distinct from later path inspection.

## Scenario-local rules

`MONITOR_FOR_OPENING` plus Drew's already-enacted player-channel attention can produce an observed opportunity and nerve adjustment. This is an explicit room rule, not a universal Function law. The 62:38 first-Cue/second-Cue share is one prototype-local default, not canonical ratio doctrine.

## Function boundary

Function reinterpretation is not implemented: `intendedFunctionId` and `interpretedFunctionId` remain equal. Player-selectable Functions are labeled `OPERATIONAL` or `PARTIAL`; the latter contribute real pressure but do not promise a universal state mutation.

## Transfer boundary

A generic accepted exchange cannot authorize transfer. The structured proposition must carry `requestedAction: OFFER_TRANSFER`, acceptance must create that commitment, Drew must offer, and bilateral acceptance/completion must match. No generated string or message ID participates in this logic.

## Deliberately absent

PSG imports/adapters, new semantic doctrine, new Vibe mappings, variable Cue weighting, richer inference, generalized opportunity, generalized joint-action sockets, environment actions, free text, runtime models, backends, authentication, multiplayer, and visual redesign are outside v0.2.1.
